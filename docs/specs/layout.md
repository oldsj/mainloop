# Layout

Mainloop is responsive across mobile and desktop viewports.

Project pages load repository details before showing project controls. If that request fails,
the page shows the load error and a **Retry loading project** button instead of remaining on
the loading message. Retrying requests the details for the current project.

## Desktop

- On home (`/`) the centre column is the Mainloop chat alone: one scroll (the thread), the composer at the bottom, nothing stacked above or below it. Other pages scroll in the same column.
- The shell is monospace, as a terminal is: the sidebar, the tab strip, the status bar, the transcript and its composer, and anything that is code (ids, branches, commits, paths, schedules, a task's brief). The monospace font is SF Mono where the browser has it to give (Safari on Apple platforms, or any browser on a machine with SF Mono installed) and otherwise **Geist Mono**, which the app serves itself, so nobody installs a font and nothing is fetched from a font service. Geist Mono is one variable file (about 71 KB, every weight), under the SIL Open Font License, with its licence served at `/licenses/GeistMono-OFL.txt`; it is preloaded and cached for good like any other built asset, and text shows in the fallback until it arrives rather than staying blank. Pages keep the system's sans font for their headings, buttons, forms and status rows.
- A conversation fills its pane from the left edge, as a terminal does: the transcript and its composer are as wide as the pane, and stop spreading at about 180 characters (90 rem) on a very wide window, where the rest of the pane is left empty on the right. The scroll area and the session row above it stay the full width of the pane. On the desktop the composer's text is the transcript's size; on a phone it is 16 px, so the browser does not zoom in on focus.
- The desktop has no top header. Left to right it is an **activity bar** of icons, as an editor has; the **sidebar** (spaces and their agents), as a terminal workspace manager has; and the page under a **tab strip**; with a **status bar** along the bottom.
- **Activity bar** (44 px wide): Mainloop's mark (a prompt and its cursor, the same drawing as the favicon), which opens the main chat; **Inbox**, which opens the answer view and carries the Needs-you count as a red badge (its accessible name includes the count: "Inbox, 3 need you"); **Spaces and agents**, which hides and shows the sidebar and is pressed while it shows; **Search**, which opens the command palette; and at the foot **Orchestration health**, **Settings** and the theme menu. Inbox, Orchestration health and Settings are marked while their page is showing.
- **Tab strip** (one line, above the page and outside its scroll): the agents of the current space, as a terminal workspace manager shows one tab per agent. The current space is the one the page belongs to (see the sidebar's spaces). In the main thread's space the first tab is **main**, the main chat. In a project with a [standing supervisor](project-supervisor.md) the first tab is **supervisor**, and the project's page is reached from the space's row in the sidebar (it then has a last tab, **overview**, while it shows). A project that has no standing supervisor yet leads with **overview**, the project page. Then come the space's other agents in the sidebar's order, each a status dot and its title, cut at about 24 characters with the full title as the tooltip. The tab for the page being shown is filled in the accent colour and marked as the current page; an agent's tab is lit on its task page and on its session. A page that is none of these (the Inbox, Settings, orchestration health, schedules) gets a last tab of its own, named for it (`inbox`, `settings`), so one tab is always lit. The strip ends with **+**: in a project it opens the main chat with `Start a task in <project>: ` in the composer, unsent, and in the main thread's space it opens the main chat. When the tabs do not fit, the strip scrolls sideways and keeps the lit tab in view. The phone has no strip yet.
- **Sidebar**: beside the activity bar, 240–480 px wide (default 300), resizable from its right edge (the right arrow widens it), and hidden with its own button, with the activity bar's **Spaces and agents**, with **⌘B** on a Mac, or with the prefix and **b** on any platform (see the prefix keys). The shortcut works while typing. The activity bar's button, the shortcut or the status bar's working count brings it back. Its width and whether it is hidden are kept per browser in local storage. It holds two lists, **spaces** and **agents**, with one row of words between them:
  - **new** starts work in the current space the way the tab strip's **+** does: in a project it opens the main chat with `Start a task in <project>: ` in the composer, unsent; in the main thread's space it opens the main chat.
  - **menu** opens the command palette, as the activity bar's **Search** does. The row is there while the lists are still loading.
- **Spaces and agents** (the sidebar's two lists), laid out as a terminal workspace manager's side column: monospace, lowercase list names, no boxes.
  - **spaces**: **main** first (the main thread's own space; not called Mainloop, since a project can be), then each project by its short name (`widgets` for `acme/widgets`; the full name is the tooltip). A space has the status dot of its most urgent agent (red over amber over teal over hollow) and one muted line counting them: `1 needs you · 2 working · 1 problem · 1 finished`, each part left out when it is zero, or `idle`. main opens the main chat; a project opens its page.
  - **agents**, under their space's name, in the spaces' order: the main thread (**Mainloop**: `Idle`, `Working` or `Needs you`, speaking for everything it directs, with the same Needs-you count as every badge); each task that has not ended, that needs the owner, or that finished in the last seven days and has not been looked at; and each live session that belongs to no task. A task or session whose project is not loaded is under main. A finished task that has been looked at leaves the list (its project's page still has it), except while its own page or its session's is the one showing.
  - A project's standing supervisor is always listed, first among its project's agents, as **supervisor**, with the tasks it directs after it, one step in. At rest (waiting for its next message) its dot is hollow and its line reads `Idle`, or its children's progress while any are running; it is then not counted as working, by its space, by the main thread's row or by the status bar.
  - An agent's row is the status dot, its title, and one muted line: where it stands, then its age, for example `Running · 3h`. A long line is cut before the age, never through it, and the full line is the tooltip. Where it stands is what the owner is asked when an owner action names the task (the row is then red), when it comes back for a task set aside, its pull request for one ready to be looked at or landing (`PR #12 · CI passing`), and otherwise its status. A coordination task says `supervisor` first, then its children's progress, and the tasks it directs follow it, one step in. Within a space, agents keep the order they were started in, so a row does not move as its state changes.
  - Opening an agent shows what it is doing: a task that has not ended and has a session opens on that session's conversation, from its row and from its tab. A task that has ended, has no session yet, or that Mainloop is recovering (a stall, a lost session) opens on its task page. A conversation that belongs to a task has **Task · <state>** in its one-row header, which opens the task page; it is in the Needs-you colour while the task waits on the owner, since that step is on the task's page and not in the thread (on a phone the link is the word **Task** alone).
  - The agent whose page is showing (its task page or its session) is filled and marked as the current page; the space that page belongs to is filled too. A page that belongs to no project (the Inbox, Settings, orchestration health, schedules) is main's.
  - The two lists are one stop for the Tab key: up and down move through every row, Home and End go to the ends, Enter opens. An agent has **Ask Mainloop** on hover or keyboard focus, and the **a** key; right-click, Shift+F10 or the menu key open the row menu (**Open**, **Ask Mainloop**).
  - An owner action that belongs to no task is counted by the main thread's row, the activity bar's **Inbox** and the status bar, and answered in the Inbox.
- **Prefix keys**: **Ctrl+B**, then one key, as a terminal workspace manager has them. They work on every platform and while typing; the key after the prefix is not typed.
  - **n** and **p**: the next and the previous tab of the current space, wrapping. A tab that leads nowhere (the page's own last tab) is passed over.
  - **1** to **9**: that tab.
  - **c**: new, as the sidebar's **new** and the strip's **+**.
  - **b**: hide or show the sidebar.
  - **w**: show the sidebar and put keyboard focus on the current space's row, from where the arrows move and Enter opens.
  - **g**: the command palette.
  - The same actions are rows in the command palette (**Next tab**, **Previous tab**, **New task in <project>**, **Hide or show the sidebar**, **Go to the spaces**), each with its key beside it, so they can be reached where something takes the prefix (a browser extension, a screen reader's browse mode) or without knowing the keys. On the phone the rows are there without keys, and the sidebar's row is **Show or hide the spaces and agents**.
  - While the prefix waits, the status bar lists these keys. The wait ends after two seconds, on Escape, or on any other key, which is then typed as usual; a key with ⌘, Ctrl or Alt held is left to the browser.
  - Costs, both deliberate: on a Mac, Ctrl+B in a text field is no longer the system's "back one character"; and off a Mac, Ctrl+B alone no longer hides the sidebar (the prefix and **b** does).
- **Command palette**: one field over the page that jumps to any task, session, workspace, project, schedule or Needs-you item, to a page (main chat, Inbox, Problems, orchestration health, scheduled runs, Settings, import a project), changes the theme, or asks Mainloop. It opens with **⌘K** on a Mac and **Ctrl+K** elsewhere, never both on one platform (on a Mac, Ctrl+K in a text field is the system's "delete to the end of the line" and is left alone), and the same key closes it; it works while typing. It also opens from **Search** on the activity bar and on the phone's bottom bar, and from **menu** in the sidebar's row of words. After the pages it lists the shell's own commands (see the prefix keys), then every task, session, workspace, project, schedule and Needs-you item, each once, what needs the owner first, then the themes, at most 50 rows. Typing narrows the list: every word must be in a row's title or the muted words beside it (its project, its state, its kind); a title that starts with the query comes first, then a word that starts with it, then the rest. Up and down move and wrap, Enter opens the row, Escape closes. The platform's modifier with Enter asks Mainloop about the highlighted row (the same prefill as an agent row's **Ask Mainloop**), and a query always ends with a row that puts the query itself in the main chat's composer, unsent.
- **Status bar** (24 px): on the left the connection, **Connected** with a green light, which links to orchestration health, and beside it the prefix keys while the prefix waits; on the right **N need you** (or **Nothing needs you**), which opens the answer view, **N working** (the agents with an amber dot in the sidebar, so the two agree), which shows the sidebar if it is hidden, and **N problems**, which opens the Problems view. While the backend is unreachable the whole bar turns to the offline colour and reads **Offline since HH:MM · reconnecting…**; nothing is added above the page, so nothing moves. Unreachable means the `/health` probe got no answer (or the browser reports no network): a single request that fails while the probe still answers makes the probe run at once, and does not turn the bar, disable actions or re-read everything. Needs you and problems are the same lists the Inbox draws. The counts stay on screen when the sidebar is hidden. Until the first read answers, the counts are not known, so the bar says **Loading…** in their place, never "Nothing needs you"; if that read fails it says **Counts unavailable**.
- The answer view (`/inbox`) shows in the centre column in place of the chat. It holds **Needs you** (questions, plan reviews and approvals, answered in place) and **Activity**. A link that names an item (a task's **Open Inbox** link) brings that item to the top under the view’s sticky header, and marks it; old `?tab=inbox` links open the view too. A back link returns to the chat.
- Buttons, fields, links and menu rows are 28 px tall with a mouse or trackpad and 44 px tall on a touch screen. Rules between regions are quieter than the edges of fields.
- Digits are the same width everywhere in the app, so counts, ages and times line up and do not shift as they change.
- A row has one status dot, in the same language as herdr's agent list: **filled amber** is working (a task that is running, or waiting on CI or another task); **filled red** is **Needs you** (a question, an approval, or a failure that needs a decision; the line under the title says which); **filled teal** is finished and not yet looked at; **hollow** is at rest (idle, asleep, cancelled, or finished and seen). Accent blue is never a status. The session row above a conversation uses the same dot, so "ready" and "asleep" are hollow. Green is the connection light in the status bar only.
- A completed task, or one whose pull request is ready for review, is "not yet looked at" until its task page, or the page of its session, has been opened; a task that changes after that is unseen again. The record is the owner's, on the server ([seen](seen.md)), so a task opened on the phone is seen on the desktop too. The page marks the task when it opens, and again when the task changes under the owner while it is a row that shows seen-ness; a task already marked after its last change is not written again, and a running task is marked once per status, not on every update. A task that last changed before the owner's record began counts as seen. Until the record has been read, or if it cannot be, nothing shows as unseen; a mark that fails is not recorded and is tried again on the next change or visit.
- Every page has one top-level heading: the main chat's is **Mainloop chat**, for screen readers only, and the answer view's is **Inbox**, with each item's title a level below it. On a sidebar row that is hovered or marked, the muted line under the title takes the row's foreground colour, so it stays readable on the selection background.
- The desktop sidebar's first row is its first list's name, **spaces**, and the button that hides it. The hint **Ask Mainloop to start, stop or change anything.** shows in the empty main chat, above the suggestion chips.
- A project is imported in Settings, at its import section (`/settings#import-project`), which the command palette opens (**Import a project**). There is no create button: none for tasks, agents or workspaces, and the sidebar's **new** and the tab strip's **+** only fill the main chat's composer. Work starts from the main chat. The project page has no create control either; `/agents` is reachable by URL only.
- An empty main chat shows suggestion chips inside the empty thread (they go once the thread has messages): **What needs me?**, **Start a task in <first project>:**, **What’s running?** and **Pause a schedule:**. Each fills the composer without sending.

## Mobile

- One agent, full screen, between two bars. There is no header.
- **On top**, the current space's **tabs**, the same as the desktop's tab strip. They scroll sideways, with the lit tab kept in view and **+** at their end.
- **At the bottom**, the desktop's activity bar laid flat, where a thumb reaches: four items, each an icon over a word, 44 px tall.
  - **Chat** (Mainloop's mark) opens the main chat, and is marked there.
  - **Inbox** opens the answer view (`/inbox`). It shows the Needs-you count as a red badge, its accessible name includes the count ("Inbox, 3 need you"), and it is marked while the answer view shows.
  - **Agents** opens the spaces and agents over the page (`?tab=explorer`, so the phone's Back puts them away; pressing it again does too). It is marked as expanded while they show.
  - **Search** opens the command palette, which is the way to orchestration health, Settings, scheduled runs, transcript search, importing a project and the themes.
- The lists are the desktop sidebar's: **spaces**, the row of words (**new**, **menu**), then **agents** under their space's name. Rows are 44 px touch targets, and an agent's **Ask Mainloop** button is always shown. Choosing a space, an agent or a tab opens its page and puts the lists away.
- The page under the lists is built the first time it shows and then stays mounted while the lists cover it, so a conversation keeps its place. A draft in the composer is kept by the draft store.
- The answer view has a back link to the main chat, as on desktop.
- The bars and the page stay clear of the device's safe areas (notch, rounded corners and the home indicator): the shell pads its top and its sides, and the bottom bar takes the bottom.
- Old `?tab=` values `sessions` and `projects` open the spaces and agents; `?tab=inbox` opens the answer view.
- The tree of groups (Needs you, Working, Since you were here, Projects, Schedules, Finished recently, Insights) that the phone used to show is gone: the agents' rows say where each stands, the Inbox counts what needs the owner, and the offline banner says when the backend is unreachable.

## Shell

- On the phone the offline banner is one line at the top of the screen. It takes its height from
  the page, so the tabs, the composer and the bottom bar stay on screen at 390 × 844. Long text is cut off with
  an ellipsis. On desktop there is no banner: the status bar says it (see Desktop). Once the
  owner's sign-in has lapsed and a reload did not restore it, the same place reads **Signed out**
  with **Sign in again** ([authentication](authentication.md#the-web-app)).
- Each page sets the document title, for example **Health · Mainloop**.
- A route change moves keyboard focus to the main landmark, so focus does not fall back to the
  page body.

## Home

- **Home is the main chat.** The work list, the home strip and the separate Since strip were removed; the sidebar's spaces and agents (see Desktop) hold the work.
- **Visits**: when the app shell opens it records one visit on the server (`POST /seen/visits`; see [seen](seen.md)). One visit is recorded per page load. Because the shell is on every route, the visit is the app's last open, not only the last time home was shown. Nothing in the web app compares against the previous visit any more: the **Since you were here** group, which did, was removed with the tree of groups. The records this browser used to keep (`mainloop.home.lastVisit`, `mainloop.seen.v1`) are removed.
- **Updates**: the lists refresh from the same task invalidation as the task pages. The relative times refresh each minute on the page.

## Tasks

Durable tasks are read from the owner task API (see [tasks.md](tasks.md)). The page shows what the
server reports; it never decides a task's state locally.

- **Project page**: the shared page header (a back link to the main chat, the repository's avatar and name, its description) in the same column as every other page, then its links and **On this page**. A **Tasks** section lists the project's tasks as a tree, supervisors with their child tasks beneath them. Beside its heading is how many of the project's workers are running, for example `2 of 6 workers running`, once the [worker limit](tasks.md#project-worker-limit) has been read. A child whose parent is not loaded is still listed. Each row is one line: the status dot (the explorer's language: amber working, red needs you, hollow at rest; a failed task that asks nothing is at rest once it is seven days old, as in [the Needs-you count](inbox.md)), the title, its state in muted text (`supervisor` for a coordination task, the status and reason, any operation in progress, and CI), and how long ago it changed. CI is shown only when it is known (both head SHAs present and equal and a valid observation no older than ten minutes) and the task is not finished; a row never says "CI unknown". A child is stepped in under its parent with a guide line for each level, and a hairline sets each top-level task and its children apart from the next. On a narrow screen the state is cut to the status word. A cancelled top-level task is folded away with everything under it, behind one row at the end of the list, **Show N cancelled tasks** (then **Hide cancelled tasks**), so a long-lived project leads with its live and finished work; a cancelled task with anything still open under it is never folded, a cancelled child stays with its parent, and a project with nothing but cancelled tasks lists them as they are. Under the page's title, **On this page** has **Memory**, **Instructions** and **All settings**, which go to those sections however long the task list is; Instructions and All settings open the folded Settings first.
- **Loading:** the sidebar's lists wait for the projects as well as the tasks, so an agent is never drawn under **main** and then moved to its project; until both have answered the lists hold their placeholder rows, and the tab strip shows only the tabs that are certain (**main** and the page's own, or none on an agent's or a project's page). The status bar's counts do not wait for the projects. While the sidebar's lists, a project's task list, a task page or a project page first loads, placeholder rows in the shape of what is coming hold its place (a dot and a line per row at the row height; a status, title and facts line for a page), so nothing jumps when it arrives. The placeholders are hidden from a screen reader, which hears the status line (`Loading Mainloop…`, `Loading tasks…`, `Loading task…`, `Loading project...`); that line is not shown. The pulse stops for reduced motion.
- **Page width:** Settings, Scheduled runs, a schedule, New schedule, Orchestration health, a workspace and the New agent page sit in one centred column, a reading width (56 rem), so a title is in the same place on each and a field is never the full width of a wide window. The task page uses the full width of the centre; the project page keeps its own narrower column.
- **Page header:** Settings, Scheduled runs, a schedule, New schedule, Orchestration health, a workspace and the New agent page share one header: a back arrow (first on the row, named by where it goes, on pages that sit under another), the page's name as its one `h1` at one size, a status, and the page's own actions on the right, with a short description under the row. The task, session and project pages have their own headers with the same back arrow and title size.
- **Task page** (`/tasks/<id>`): the task and its parents and children; the active provider and native session; the workspace, environment version and branch; the attempt history, including superseded attempts as read-only history; PR, CI and merge as separate facts, with how long ago they were observed (flagged stale after ten minutes); a task with a repository or branch and no pull request says **No pull request yet.**, and a task with no repository, branch or pull request shows no workspace or pull request section at all; the session ID shows as 8 characters with a copy button; the step and last confirmed step of any open provider switch or other operation, under **In progress**, or **On hold** when every open operation is blocked or uncertain (one sentence, for example `Create is blocked after “Creating the new attempt”: workspace provisioning is not available yet`, then the steps on one line, kept apart by `›`, each finished one marked `✓` and the one under way `●`, so a step's state is never colour alone); and the provider's own summary, labelled **Provider summary; unverified**. A report or finished turn is never shown as proof the task is complete. PR links open only when they are `https` URLs, in a new tab with `rel="noopener noreferrer"`.
- Failed task reads, including background updates and reconnects, show a last-known-state warning and retry control on the task page. The warning clears after a successful read of that task; list failures are tracked separately.
- **Actions**: **Retry**, **Reassign** (to the other provider, chosen from the profiles that offer the attempt's role) and **Cancel task** (not shown once the task has ended). On a project's [standing supervisor](project-supervisor.md) the first is named **Restart**, since that is what the server's retry does there (a new session on the same task, its workers kept), with a line under the buttons that says so; Reassign and Cancel task are not shown, because the server refuses them for good. Each is enabled only when the server's eligibility says so, and sends the task version and attempt shown on the page. If the task changed first, the server refuses with a conflict and the page re-reads the task. If a response is lost, a dedicated **Resend original request** control shows the original target, version and attempt and reuses the same request. It remains available when eligibility or the current provider changes, and is disabled while a request is in flight. The notice says the outcome is unconfirmed. Pending approvals and a required checkpoint are listed as blockers.
- **Updates**: `task:updated` events only prompt a re-read; duplicates are ignored, and after the event stream reconnects the page re-reads every task it holds.
- **Links**: the session and workspace pages link to the task that owns them (noting when the attempt is superseded), and an Inbox approval card links to its task. Approvals are still answered in the Inbox; the task page only points to it.
- **Mobile**: the same sections in a single column. Buttons and the provider options are at least 44px tall.

## React status (F5)

- **Superseded by the explorer:** the always-mounted inbox panel and the compact Inbox tab with its two badges. Attention and owner tasks now poll while the explorer is mounted and the page is visible, on both layouts: attention every 4 s, and the owner task list every 4 s while the event stream is down and every 30 s while it is open (each task change arrives as an event that re-reads the list, so the poll is then only a safety net, and the list is the largest thing the app downloads; when the stream drops the list is read at once); the phone's bottom bar, and the activity bar's Inbox and the status bar on desktop, carry the Needs-you count; and the answer view at `/inbox` mounts the same inbox panel. Inbox buttons, links and the reply field are at least 44 px tall.
- **Desktop count:** on the activity bar's **Inbox** and in the status bar; the main thread's row in the sidebar turns red with it.
- **Checked in a browser (fixtures, not live):** 390×844 and 1440×900 against the MSW dev server. Playwright journeys are deferred to F9.
